What changed

초안은 정보는 충분했지만, 같은 이야기를 여러 번 하고 정작 "왜 이걸 사야 하는지"는 첫 화면에 없었어요. 바꾼 것들을 정리했습니다.

  1. 첫 화면제품명 + 설명 문단스크롤을 멈출 이유가 없음. 모바일 첫 3초에 메시지가 안 보임.영문 선언 + 한 줄 훅"운동으로 만든 등, 이제 가리지 마세요." 핵심 스펙 4개를 바로 아래에.
  2. 구조같은 내용 3번 반복No Adjusting / Key Features / How It Is Made가 모두 패드·백리스·핏을 설명.문제 3개 ↔ 해결 3개 1:1 매칭패드가 뜸 → 일체형 패드, 밑단 말림 → 2겹 밴드, 등이 가려짐 → 백리스.
  3. 문제 제기없음기능만 나열하는 정보형 톤.세트 사이 장면으로 공감오버헤드 프레스, 데드리프트, 랫풀다운처럼 타깃이 실제 겪는 순간을 짚음.
  4. 사회적 증거페이지 후반 08번B안은 해결 직후로 당김"정말 그럴까?" 하는 순간에 실제 착용컷을 보여 줌.
  5. 세트 할인"Shop the set" 버튼만5,000원 할인이 안 보임.가격표로 보여 줌36,000 + 32,000 = 68,000 → 63,000원. 객단가를 올리는 가장 쉬운 장치예요.
  6. 사이즈 안내세 곳의 말이 다름Fit "큰 쪽", FAQ "평소 사이즈", Notice "실측보다 여유 있게".한 문장으로 통일"평소 사이즈, 어깨·등이 발달했거나 두 사이즈 사이면 한 치수 위."
  7. 컬러베이지·남색 회색이 섞임#F2F1EF, #23242A 때문에 흑백 원칙이 흐려짐.순수 흑백, 컬러는 옷에만4가지 컬러가 페이지에서 가장 강하게 보이도록.
  8. 법정 표기일부 누락안감 소재, 제조국, 수입자, 세탁기호가 없음.세탁기호 5종 + 상품정보 고시표 추가종이택 분쟁을 막는 데도 도움이 돼요.
  9. 섹션 번호01–12 번호순서가 의미 없는 번호라 읽을 거리만 늘어남.영문 아이브로 라벨로 교체번호는 실제 순서가 있는 FIX 01–03에만.
  10. 모바일1200px 데스크톱 기준모바일 우선, 최대 960px390px 폭에서 가로 스크롤 없이 확인. 스크립트 없이 CSS만 사용(카페24 에디터 호환).

Recommendation

Go with B. Borrow A's calm.

지금 단계는 광고로 처음 들어온 사람을 설득해야 하는 시기예요. 젝시믹스·안다르 같은 파스텔 상세페이지 사이에서 바로 구분되는 건 B입니다. 브랜드가이드에서 아직 정하지 않은 "럭셔리 절제 vs 하드코어" 톤도 B 쪽으로 기울이는 걸 권해요. 다만 사이즈·FAQ·고시 정보 구간은 A처럼 흰 바탕에 여백 넓게 두면 읽기 편합니다(현재 B도 그 구간은 밝은 블록으로 처리).

Before launch

시안에 노란색으로 표시한 곳 포함, 올리기 전에 대표님 확인이 필요한 항목이에요.

  • 모델 정보 · 키와 착용 사이즈가 아직 000cm로 비어 있어요.
  • A/S 책임자 연락처 · 상품정보 고시표에 기입 필요.
  • 색상명 정리 · 판매명(블랙·차콜·밀크 블루·버건디)과 실제 발주 색(블랙·슬레이트 그레이·콘플라워 블루·겨울베리)이 달라요. 옵션명, 상세, 택 표기를 하나로 맞춰야 교환 문의가 줄어듭니다.
  • 착용 후기 사진 출처 · 실제 구매 고객이 아니라면 "실제 구매 고객"이라고 쓰면 안 됩니다(표시광고법). 시안은 "헬스장에서 찍은 사진"으로만 표현했어요.
  • 실측 재확인 · 총장이 S→M 3cm, M→L 1cm로 간격이 고르지 않아요. 오기인지 확인해 주세요.
  • 단정 표현 · "비치지 않습니다", "밀려 올라가지 않아요"는 실제 착용 테스트 근거를 갖고 계시면 그대로, 아니라면 "걱정을 줄였어요" 정도로 낮추는 게 안전해요.

Better process

다음 상세페이지(3부 쇼츠, 텐션핏 롱티)부터는 이 순서로 가면 수정이 훨씬 줄어요.

  1. 카피덱 먼저, 디자인은 나중에

    섹션별 영문 헤드라인 · 한국어 훅 · 근거 문장을 표 한 장에 먼저 확정합니다. 이번 초안처럼 같은 내용이 세 번 나오는 문제는 이 단계에서 걸러져요.

  2. 문제 정의는 리뷰 데이터로

    경쟁사 홀터·브라탑 리뷰에서 불만 키워드(패드 뜸, 말림, 비침 등)를 모아 빈도순으로 문제 섹션을 짭니다. 감이 아니라 근거로 고르는 거예요.

  3. 샷리스트를 상세페이지에서 역산

    "패드가 안 뜬다"는 사진 한 장보다 팔을 끝까지 올리는 3초 GIF가 강합니다. 섹션마다 필요한 증명 컷을 먼저 정하고 촬영(또는 힉스필드 생성)하세요.

  4. 채널별로 내보내기

    스마트스토어는 HTML을 넣을 수 없어 이미지로 올려야 해요. 이 HTML을 860px 폭 이미지 조각으로 자동 저장하는 스크립트를 만들어 드릴 수 있고, 카페24에는 HTML 그대로 올려 텍스트 검색 노출을 챙기면 됩니다.

  5. 섹션을 모듈로

    Hero · Problem · Fix · Fabric · Colour · Proof · Set · Size · FAQ · Care 블록을 템플릿으로 고정하면 다음 제품은 내용만 바꿔 끼우면 됩니다.

  6. 첫 화면은 광고로 먼저 테스트

    "Built to show the work." 와 "Don't stay subtle." 두 훅을 메타 광고 소재로 붙여 클릭률을 비교하고, 이긴 쪽을 상세페이지 첫 화면으로 씁니다.

  7. 오픈 후 스크롤 데이터 보기

    카페24에 무료 히트맵 도구(MS Clarity 등)를 붙이면 사람들이 어디서 이탈하는지 보여요. 이탈 구간부터 다음 수정 대상이 됩니다.
