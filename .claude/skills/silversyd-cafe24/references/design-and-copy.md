# 디자인과 문구 기준

## 1. 누구에게 파는가

- **타겟:** 고중량 운동을 하는 2030 여성. 운동은 진지하게 하고, 운동한 몸이 어떻게 보이는지도 중요하게 생각한다.
- **무드:** 펑키, 시크, 날렵. 헬스 인플루언서, 댄서, 래퍼를 떠올리면 된다. 레퍼런스는 짐샤크, 알파리트, 스킴스, 나이키형 미니멀.
- **림빅 유형(사용자가 쓰는 4분류):** 1순위 성과형(결과를 눈으로 확인, 근거 선호, 과장 싫어함). 2순위 혁신/자극형(새롭고 감각적인 무드). 안정형 레버(사이즈, 비침, 불편 해소, "많은 사람이 샀다")는 구매 직전에만.
- **브랜드가 일관되게 할 말:** 운동한 몸이 드러나는 옷.

## 2. 상세설명 공통 골격 (네 라인 동일, 공통 u1)

| 순서 | 고객 마음 | 섹션 |
|---|---|---|
| 1 | 인지 | 커버 |
| 2 | 인지 | 개요(훅 한 문단, 상세정보 2x2) |
| 3 | 관심 | 스테이지와 만든 이유 |
| 4 | 관심 | A Closer Look: 사진 중심 디테일(Spec detail) |
| 5 | 설득 | Why It Works: 원단과 핏 3가지, 검정 배경(Main detail) |
| 6 | 안심 | FIT TIP 띠 |
| 7 | 안심 | Every Angle(사진 있는 상품만) |
| 8 | 안심 | 착용컷, 룩북, 모델 노트 |
| 9 | 선택 | 컬러 4 |
| 10 | 구매 | 함께 사기 1개(상품 링크) |
| 11 | 구매 | 사이즈, FAQ, 브랜드 |

- 디테일(흰)과 Why It Works(검정) 순서는 검정 섹션 연속을 피하려고 정했다. "눈으로 본 다음 이유를 듣는" 흐름.
- 기획 제안은 섹션마다 "고객 마음 한 줄 + 담당 디렉터 포인트" 표로 하면 사용자가 좋아한다. 공급자 기준 스펙 나열 순서(개요, 디테일, 소재, 컬러)는 반려된다.
- 브랜드 기획자 기획안의 main detail, spec detail 포인트는 **전부 강조돼야 한다.** 단 표현은 그대로 옮기지 말고 고객에게 와닿게. 중심은 「예쁘다」. 기능 나열과 문제해결형(납작하게 눌림 설명 위주)은 반려됐다.

## 3. 디자인 토큰

- 폰트: Montserrat(영문 제목, 라벨) + Noto Sans KR(국문). 제목은 영문, 설명은 국문(국문 제목은 번역투로 읽힘). 리뷰 등 새 화면에서 Pretendard 본문 제안이 진행 중.
- 크기: 12 라벨 / 14 본문 / 16 리드 / 20 소제목 / 52 대제목(태블릿 44, 모바일 34) / cqw 디스플레이.
- 색은 무채색만: ink #111, sub #5E5E5E, faint #9A9A9A, silver #8A8A8A(라벨, 다크 위 #A3A3A3), rule #CFCFCF, stone #E7E7E7, night #121212. **검정 가로선 금지.** 할인율 빨강 #b3261e(목록 카드).
- 가로선: 묶음 경계만(FAQ 문항, 표 머리줄, 링크 밑줄, 브랜드 서명, 모델 노트). 항목마다 반복되는 선 금지. 그렇다고 전부 지우면 반려(「전부 없애란 게 아님」). 짧고 굵은 강조선 금지.
- 끝선: 사진과 배경은 컨테이너 끝까지(0~1200), 글은 안쪽 44px 선(모바일 20px).
- 이미지 라운드: 상세설명 사진 0. 사이트 UI 기준(리뷰 작업에서 제안): 이미지 8 / 카드 12 / 모달 16 / 버튼 pill 48h.
- 섹션명은 번호 없이 제목 위 한 줄 오른쪽 정렬(`.sd__ttl`). 라벨 형식 「01 Pad | 가슴 패드」. 모바일 캡션은 「| 국문」이 줄 첫머리에 오지 않게 국문을 아랫줄로.
- 외곽선 글자는 SVG 경로(겹침 합친 path, vector-effect 균일 두께)로. `-webkit-text-stroke` 와 feMorphology 필터는 Montserrat 겹침선, 사선 두께 문제로 폐기.
- 레퍼런스 요소(가격 박스 등)는 그대로 복제하지 않고 우리 문법(얇은 선 요약 등)으로 바꾼다.
- 반응형은 `@container` 기준(상세설명 컨테이너 sd). 761~1000 태블릿 구간에서 넘침 버그가 자주 났다. `minmax(0,...)`, `min-width:0` 을 습관적으로.
- 섹션 이름 통일: Overview / Why We Made It / A Closer Look / Why It Works / Fit Tip / Every Angle / Worn By People Who Lift / Four Ways To Wear It / Pair 또는 Match / Measure Before You Buy / Before You Train.

## 4. 문구

- 고객이 실제 할 법한 짧고 담백한 말. 해요체 중심, 습니다체 혼용 가능.
- 반려된 예(쓰지 말 것): 「큰 로고 대신 이 구조를 브랜드의 표시로 두었다」, 「훈련으로 만든 몸의 선이 옷보다 먼저 보이도록 한 선택」(AI 같음), 「YOU CAME TO TRAIN, NOT TO ADJUST」, 「당신이 만든 등이니까요」(과장), 「이 한 장」, 「~하게, ~하게」 형용사 반복, 「Best with ...」 상황 예시 줄(오글거림), 「NO GAPS」(안 와닿음).
- 확정된 예: 취소선 불평 한 줄 「홀터넥이라 브라끈이 보임」, 「등 운동을 하는데 등이 안 보임」(음슴체 불평). 01 제목 「브라 없이 홀터넥 한 장으로」. 쇼츠 스테이지 「투박한 레깅스에 눌려 있던 엉덩이 라인이 살아나요」. 롱티 「Muscle Fit? Tension Fit.」. 스테이지 영문 「MATCH UP. / SHOW UP.」, 「SHAPE UP. / LIFT UP.」.
- 어휘: 리프팅 벨트, 랫풀다운 같은 리프터 어휘는 좋은 반응. 「섹시」는 허용. 「입체 셔링」 대신 「허리 주름」(Waist Shirring).
- 같은 효익을 두 섹션에서 반복하지 않는다. 디테일은 무엇이 보이는지, Why It Works 는 왜 그렇게 되는지.
- 공식 상품명을 본문에 자연스럽게 1~3회(SEO/GEO).
- FAQ 는 GEO 형으로 솔직하게(C컵 이상 사이즈업, 갑갑할 수 있음, 밀착 선호는 정사이즈나 다운). FAQ 화면 + FAQPage 스키마.
- 문구 제안은 후보 여러 개보다 하나를 담백하게 내고 피드백을 받는다.
- 확인 안 된 수치(판매량, 리뷰 수, 재구매율)와 후기는 쓰지 않는다. 「Best Seller | 문의가 끊이지 않는 실버시드 대표 아이템」처럼 수치 없는 표현은 사용자 요청으로 허용된 적이 있다.
- 가로 대시(—), 중간점(·) 금지. 원문 법률 텍스트(약관)의 가운뎃점은 원문이라 그대로 둔다.

## 5. 시안 만들기

- 시안은 단독 실행 HTML: `<!doctype html>`, `<html lang="ko">`, `<meta charset="utf-8">`, viewport, 이미지 data URI 내장(외부는 Google Fonts 정도만).
- 고정 파일명에 덮어쓴다: `주제_시안_최신.html`. 생성기(파이썬)는 버전별로 남겨도 된다.
- 여러 안 비교는 한 파일 안 탭(현재 / A / B / C ...) + PC/MOBILE 토글(폰 프레임 또는 컨테이너 폭). 추천안과 이유를 함께 적는다.
- 사용자 사진 파일명과 실제 내용이 다를 수 있다(예: `홀터넥-베이비 블루` 폴더가 실은 롱티 사진). 열어 보고 쓴다.
- 누끼는 사용자 제공 원본이 우선(자동 누끼는 머리카락 흰 테두리 문제).
- 사이트 UI 제안 시 실측(px)으로 현재 값을 먼저 보여 주고 바꿀 값을 제시하면 설득이 쉽다.
